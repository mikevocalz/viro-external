# Releasing @viro-external/specs and @viro-external/xr-contract

The two packages release together from `main`. The Viro side
(`@reactvision/react-viro`) has its own procedure in the viro repo,
`docs/specs-release.md`; do this one first, because Viro's peer range
names the version you publish here.

## Version rules

0.x semver. Bump the minor version when any of these change, the patch
version otherwise:

- a name, signature or type in `api/specs.api.d.ts`,
  `api/specs-lens-core.api.d.ts` or `packages/xr-platform-contract/api/xr-contract.api.d.ts`
  is removed or narrowed;
- the scene wire format: `wireVersion` or `sceneProtocols` in
  `lens-runtime.json`, or a field the controller rejects that it accepted
  before;
- the inputs of a Lens component a project wires by hand
  (`ViroSpecsSceneControllerHost`, `ViroSpecsAssetRegistry`,
  `ViroGeneratedSceneHost` as generated by Viro);
- a minimum in `lens-runtime.json` (`interactionKit`, `requiredPackages`).

Adding an export, a diagnostic code or an optional field is a patch.
Diagnostic codes are append-only, in both repos.

## Before the release PR

From the workspace root, with pnpm 12.8.1:

```bash
pnpm install --frozen-lockfile
pnpm --filter @viro-external/xr-contract typecheck
pnpm --filter @viro-external/specs typecheck
pnpm --filter @viro-external/xr-contract build
pnpm --filter @viro-external/specs build
pnpm --filter @viro-external/specs specs:validate-lens
pnpm --filter @viro-external/specs specs:test-lens
pnpm --filter @viro-external/specs specs:test-runner
pnpm --filter @viro-external/specs specs:test-presentation
pnpm --filter @viro-external/specs specs:test-host
pnpm --filter @viro-external/specs specs:test-reference-apps
node scripts/ci/api-snapshot.mjs
pnpm --filter @viro-external/specs specs:test-consumer
```

Every command must exit 0. `specs:test-presentation` reads `dist/`, so
it runs after `build`. If `api-snapshot.mjs` reports drift and the change
is intended, run it with `--update`, commit the snapshot, and check the
version bump against the rules above.

## Release PR

1. Set `version` in both `package.json` files. Keep the specs peer range
   on xr-contract (`^0.MINOR.0`) in step.
2. Move the `Unreleased` heading in `packages/specs/CHANGELOG.md` to the
   version and date. Each entry says what changed for a consumer and, for
   a minor bump, how to migrate.
3. Update [Compatibility.md](./Compatibility.md) when a Lens Studio,
   package or Interaction Kit row changes, and record which tier
   validated it.
4. Lens Studio Preview pass, recorded in `doc/validation/`:
   - `pnpm specs:sync -- --project <Platform Lab project> --with-validation`
     and `pnpm specs:doctor -- --project <same>`, both exit 0;
   - open the project in Lens Studio 5.22 or later, attach `LeafIndex`, run
     every scenario in the LEAF panel, including the reference apps in
     `examples/reference-apps/README.md`. Every scenario passes except the
     one named `...ExpectedFailure...`, which must fail on its named
     assertion;
   - note the Lens Studio build, the SPECS 27 Preview environment and each
     package version (`specs:doctor` prints them).
5. CI on the PR: `SPECS release gates` (`.github/workflows/specs-release.yml`)
   green, including the clean-consumer job.

## Publish

Run the `Publish SPECS packages` workflow from `main` with `dry_run: true`.
It installs, validates, builds, packs, installs the tarballs into a clean
consumer and checks the API snapshots, then stops. Read the pack listing
in the log. Run it again with `dry_run: false` to publish both tarballs
with provenance.

Publish the tarball, never the folder: `pnpm pack` applies `publishConfig`
(dist entry points); `npm publish` in `packages/specs` does not, and would
ship `src/index.ts` as the types entry.

After publishing:

```bash
npm view @viro-external/specs@<version> version
npm view @viro-external/xr-contract@<version> version
```

Then tag `specs-v<version>` on the merge commit and start the Viro release.

## Rolling back

npm does not allow republishing a version. Publish a patch that reverts
the change and `npm deprecate @viro-external/specs@<bad> "<reason>; use
<good>"`. A Lens project pinned to the bad version recovers with
`pnpm specs:sync -- --project <dir>` after upgrading.
